## LULU-11：把转换与覆盖层逐项记账

开发源码、去注释发布文件、本地作者台词与测试工具覆盖层允许字节不同；版本号和文件名不足以关联它们。可推广的是“每个输入与产物分别记录身份，并注明转换规则和覆盖层”，而非照搬本项目的排除列表。

`代码与测试/tools/package_release.py:45-67,92-149,152-192` 按 lexer 的注释 token 区间替换，保留换行或空格，随后比较默认通道的 `(token type, token text)` 序列。字符串内部空白和长字符串内容不会按行裁剪。每个 Lua 产物再过 AST、同一进程环境中的 Lua 5.1 dump 与 LuaJIT stripped dump 比较；XML 检查解析树，ZIP 检查 CRC、成员集合与逐成员 SHA。源码/发布 SHA 映射比“两个文件字节必须一样”更适合该转换。

这些检查证明受检转换的局部性质。字节码不能跨编译器、架构、版本或不同 chunk 名随意比较；LuaJIT 常量序列化还受运行环境影响，脚本特意停用 GC。相同 token 或可编译不证明 API 可用、联网正确、游戏玩法或音视频正确。CRC 也不证明资源可被引擎正确解码。独立输出目录、源码前后清单、许可保留与覆盖层隔离值得保留。

`代码与测试/tools/sync_local_mod.py:40-67,80-107,109-167` 在目标完整清单等于上次完成回执后继续，先验证 payload 与源码映射，完整备份目标，再归档已确认旧文件、以临时文件替换变化项，最后核验整份清单。作者台词、可选工具、入口追加和遗留图标均是显式本地策略。该案例提示：发布来源与本地覆盖层要分开追踪，不能从运行副本反向打包。不要把本项目“保留旧台词”推广成所有项目的默认策略。

边界：替换只到单文件粒度；回执在批次前后写入，`copied/archived` 不逐项落盘；中断后可能只有不完整回执，必须比较备份、目标和期望哈希恢复。此脚本没有通用回滚器。防护大量依赖 `assert`，Python 优化模式会移除断言；报告、清单路径也按本地可信输入处理。通用工具应另行设计显式失败检查、受限相对路径、工具版本和恢复协议，不能直接把这两份脚本当成稳健发布框架。

证据索引中的 0.9.23 发布摘录报告 265 个文件、162 个 Lua；同步摘录报告 166 个 Lua、仅修改 `modinfo.lua` 和糖袋 SG。完整报告、发布 ZIP、完整同步回执和备份未收入包内，因此这里仅复核摘录身份与脚本设计，不独立确认这些历史产物和转换结果。
