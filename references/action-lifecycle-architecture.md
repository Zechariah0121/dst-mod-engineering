# 把可取消交互接成一条完整链

一次交互要接通输入、预测、权威执行、结果显示和退出；复杂 Mod 可以沿用原版 Action、SG、组件和复制机制，只把自己的业务与资源归属补清楚。下面用“玩家对调谐台注能”贯穿说明：起手可被中断，真正结算时才按项目既定规则修改资源和台状态。名称是结构示例，费用、耗时、重复操作、退款、死亡保留与读档进度由项目决定。

## 先让职责有明确落点

| 所有者 | 负责什么 | 交给下一层什么 |
|---|---|---|
| 组件动作 collector / 输入适配 | 根据当前可见信息给出“可尝试注能”的候选；按原版输入链发起 | 玩家、目标与动作意图 |
| 玩家 SG | 起手、执行时点、状态持有的声音/FX与退出 | 到达权威执行点的 BufferedAction |
| 调谐台业务组件 | 重验条件，协调玩家资源接口和台自身状态 | 本次成功/拒绝原因及已发生的业务事实 |
| 玩家资源组件 / 台状态组件 | 各自拥有唯一的权威写入口、复制值与需保存的数据 | 供表现和 HUD 读取的结果 |
| 本地 HUD / 表现适配 | 初读并跟随复制状态；清理自己的绑定、声音与 FX | 展示与本地反馈 |

这些职责可以留在现有文件和局部函数中。只有出现不同执行端、寿命或恢复责任时再拆模块；一个普通注能动作无需新增全局 Bus、通用事务管理器或跨分片账本。

## 从点击到服务端结算

**1. 接入候选与动作。** 先检查已有 Action/组件能否表达目标行为；确有新业务才登记自定义 Action、相应组件动作和角色两端的 ActionHandler。collector 应读 tag、Replica 或公共接口来决定是否列出候选，把扣费和状态写入放到权威业务入口。原版 AddAction 建立 code/mod_name 映射；登记本身还没有接通预测或业务执行。（N01–N03）

**2. 复用移动与预览。** 普通鼠标左键装配 preview/non-preview 发送闭包；预测客户端到达目标、进入预览状态后发送完整动作请求。无 locomotor 的非预测分支在有 non_preview_cb、无 pre_action_cb 时，可先发送再做本地检查，DoAction 返回 nil 不证明未发送。不要在预览扣费或提前清动作槽。本例将角色两端接到已有 `dolongaction`；独立耗时或循环确有需要时再加配套状态。（N04–N06、N09、N12、N14–N16）

**3. 在服务器重新确认意图。** 全 nil LeftClick 是控制消息：通过远端控制器门禁后仍先清 combat 目标、标记 PRIMARY，再早退，不重建业务候选。非空请求检查点击点位置，服务器再重建候选并按 code/mod_name 匹配。起步、到达和最终 IsValid 是不同检查点，IsValid 不统一复查距离；注能业务在执行点重验玩家、目标、距离、权限和资源。本段限普通左键，其他入口另追适配路径。（N07–N11、N13–N14、N17）

**4. 把真正写入集中到业务入口。** 原版服务端 `dolongaction` 在超时点调用 `PerformBufferedAction`；客户端对应状态调用 `PerformPreviewBufferedAction`。`Action.fn` 将这次权威尝试交给台的业务接口，例如项目自定义的 `TryCharge(doer)`；这个名字只是接口示意。它负责实际检查、调用玩家资源操作、修改台状态并说明结果，SG 不再重复扣一次费用。`BufferedAction:Do` 本身没有总体 master 门禁，端别仍由实际调用链和业务组件负责。（N13、N15–N17）

建议业务接口让调用方分得清“拒绝且未写入”“已完成”和“发生过部分写入”。Action 适配层按其合同返回成功值和原因；已写入后异常或返回 false，原版 Fail 不会自动退款或撤销台状态。若一次注能只有同步的最终写入，就把执行点收在该调用里；只有确实需要跨帧结算时，才让业务组件持有任务与本次尝试身份。（N17–N19）

## 取消结束哪一段，结果由哪一段证明

本例将“取消”区分为结算前停止尝试，以及结算后停止表现。前者不再发起该次业务写入；后者保留已经发生的事实，再按项目明确的补偿政策处理。不要把两者都实现为“看到动画退出就退费”。

原版长动作在服务端退出时停止自身声音，仅在当前 buffered action 仍是入态捕获的对象、且没有对应 held-action 保留条件时才清动作；客户端退出停止预览声音。扩展自定义状态时沿用这种归属判断，不能无条件清掉新动作。`busy` 会被状态主动移除，不是不可打断的业务锁。（N15–N16、N29）

`PerformBufferedAction` 在 performaction 和主题事件之后才缓存动作，前置监听换槽可改变随后执行的对象。performaction 监听返回后槽为 nil 时，有 player tag 会在主题表达式读 nil.action；无该 tag 则因 and 短路跳过该读取，随后仍无法对 nil 执行 Do。Do 的 IsValid 假时只早退，不先 Fail，由外层 Perform 进入失败通知。成功值、回调和 `ServerStateMatches` 各说明自身阶段，结果应读权威状态；业务后还要创建 FX 时，再核对当前尝试与 SG 归属。（N13、N16–N20）

结果长期存在时，用该组件的复制状态供 HUD/其他玩家重建；短暂提示按现有表现机制发送。HUD 绑定时先读当前值，再监听变化，同值 netvar set 不保证再触发 dirty。预测起手音与权威成功音分开，避免服务器拒绝后客户端仍留下“已完成”的持续表现。（N16、N28；[联机与复制](networking-rpc.md)）

## 任务和退出跟着实际所有者走

| 发生什么 | 本例需要处理的责任 |
|---|---|
| 执行前目标移除或条件变化 | 在执行点拒绝；结束本次起手表现。未进入业务不代表所有调用方都会执行同一种失败回调。 |
| 移动、受击、死亡等导致动作退出 | SG 清自己的表现；业务组件按当前阶段停止尚未执行的任务，保留或补偿已发生事实。具体哪些输入算取消由角色状态与项目规则决定。 |
| 拆下业务组件 | `OnRemoveFromEntity` 取消该组件持有的句柄、解除精确监听并清字段。组件拆除不等于整个实体移除。 |
| 玩家或台实体退出 | 宿主 Lua Remove 在 onremove 后清当时的监听/任务，再调组件等退出钩子；后段新建资源没有统一二次清扫，其他宿主资源由本功能释放。 |
| 玩家换角、reroll 或其他实例接管 | 结束旧实例的临时尝试和输入绑定；只把明确允许延续的数据交给新实例。账号相同不使旧组件、闭包或任务自动转移。 |

组件拆除用 `OnRemoveFromEntity`，宿主 Remove 的组件通知为 `OnRemoveEntity`。跨帧任务由业务所有者持有，停止时 Cancel 后清字段；组件卸载不要用 CancelAllPendingTasks 抹掉玩家其他任务。Cancel 或 Remove 正常返回不终止原 Lua 栈，继续写入前重查本次业务归属。没有异步延续的小函数无需增加请求 ID。（N21–N23、N27；[组件与任务归属](component-task-ownership.md)）

## 读档恢复结果，不重放一次点击

玩家资源归玩家组件，台的已注能状态归台组件。若项目要求保存，再由各自 OnSave 保存可恢复数据；不要保存 BufferedAction、闭包、FX或 task handle。加载先建立缺字段默认值，再恢复基础值，最后按明确阶段重建依赖和表现。组件 OnLoad 按 pairs 分发，跨组件不依赖固定次序。（N25）

若台要保留冷却，可复用 Timer 的剩余值/暂停状态保存与加载；它只替换保存记录中的同名计时，不替所有自定义任务善后。要保存尚未完成的注能进度，则另外决定：重启取消还是继续、是否已消费、目标缺失怎么办，以及构造期任务如何交接。恢复时应用这些事实，不调用会再次扣费的“首次注能”入口。（N24–N26）

跨实体引用按实际调用方的 GUID/refs/postpass 协议修复；普通玩家 session 和世界加载并非同一套映射。OnSave 只收集保存表，不能据此承诺每次内存写入已落盘。具体接线与磁盘重启验证读[保存与恢复](save-recovery-architecture.md)。

## 验收这条链

按本次注能实现选择检查，先对一个玩家、一座台跑通正常注能，再覆盖实际可达的执行前取消、资源不足、目标在起手中移除、结算后切态及重复请求。涉及跨帧任务时，检查组件拆除/玩家换角后旧任务不得继续写入。检查资源与台的实际状态，以及所用声音、FX和监听是否结束；“没有报错”不是这些结果的替代。

涉及预测时，用远端客户端验证支持的预测配置。需要保存的结果与冷却，用同一隔离存档退出后独立进程恢复，核对恢复值且不二次扣费。涉及 HUD 的输入再验对应鼠标/手柄入口。本篇完成的是静态接入研究，没有运行上述游戏场景。
